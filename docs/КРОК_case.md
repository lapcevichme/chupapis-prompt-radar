# Промпт-радар: поиск метода для эффективной классификации запросов пользователей ИИ-агентов

**Теги:** AI Agents | Data Analytics

## Общее описание

Разработайте инструмент аналитики запросов к ИИ-агентам. Решение должно автоматически классифицировать пользовательские запросы по типам задач, группировать их в сценарии использования, делать краткие саммари по каждой группе и формировать понятный отчёт/дашборд: что чаще всего спрашивают, какие сценарии растут и где у агента возникают проблемы.

## Проблема (актуальность)

Ежедневно сотрудники пишут внутренним ИИ-агентам сотни и тысячи запросов: «помоги написать письмо», «объясни ошибку», «собери отчёт», «сформулируй ТЗ» и т.д. Но бизнесу важно понимать не просто сколько запросов, а зачем люди используют ИИ и насколько он реально полезен.

Когда ИИ внедрён в компанию, появляется “серая зона”:

- запросов много, но они разнородны;
- пользователи формулируют по-разному одно и то же;
- часть запросов относится к рабочим процессам, часть - из интереса;
- трудно понять, где ИИ действительно экономит время, а где создаёт иллюзию пользы.

Ручной анализ логов занимает недели и всё равно будет субъективным. Бизнесу нужен навигатор, который постоянно переводит шум логов в ясные решения.

## Задача

Ваша задача - разработать систему, которая:

1. классифицирует запросы пользователей ИИ-агентов (по темам/типам задач),
2. находит сценарии использования (use-cases) - устойчивые «паттерны» применения агента,
3. делает саммари по этим сценариям: что спрашивают чаще, какие боли, какие запросы «ломаются», где есть потенциал автоматизации.

На выходе - понятный отчёт/дашборд для руководителей: что происходит с ИИ в компании и куда развивать платформу.

## Стейкхолдеры

CTO КРОК - они хотят:

- видеть эффективность внедрения ИИ в компании (по направлениям и командам),
- понимать топ-сценарии и топ-проблемы,
- принимать решения: какие агенты развивать, какие сценарии автоматизировать, где обучить пользователей.

Другие стейкхолдеры:

- сотрудники компании (пишут запросы агентам),
- владельцы платформы/агентов (улучшают агентов),
- аналитики и продуктовые менеджеры (собирают инсайты),
- руководители (смотрят отчёт и решают, что делать дальше).

## Как сейчас решают (и почему не работает)

- смотрят выборку логов руками,
- считают «сколько сообщений» и «сколько пользователей»,
- ищут по ключевым словам,
- проводят опросы.

Минусы: долго, субъективно, сложно увидеть новые сценарии и тренды.

## Что будет, если не решать

- компания тратит деньги на ИИ, не понимая отдачи,
- улучшения делаются «на глаз»,
- важные сценарии остаются незамеченными,
- повторяются одни и те же ошибки пользователей -> ИИ кажется «плохим», хотя проблема в формулировке/интерфейсе.

## Ожидаемое решение

Система, которая превращает логи в структурированную аналитику.

### Минимальный функционал (must-have)

#### 1. Классификация запросов

Присвоить каждому запросу категорию (или несколько).

Примеры (можете придумать свои):

- генерация текста (письма, инструкции, посты),
- помощь с кодом,
- анализ данных/таблиц/SQL,
- объяснение/обучение,
- поиск/сбор информации,
- планирование/управление задачами,
- «нерабочее / общие вопросы».

#### 2. Поиск сценариев использования (use-cases)

Найти группы похожих запросов и назвать их как «сценарии».

Пример:

«Написание деловых писем» -> отдельный сценарий внутри «генерации текста».  
«Объяснение ошибок Python traceback» -> сценарий внутри «помощи с кодом».

#### 3. Саммаризация по категориям/сценариям

Для каждой группы: что это за сценарий, зачем он, какие типовые формулировки.

#### 4. Отчёт/дашборд

Понятная выдача: таблица/веб-страница/презентация/ноутбук.

Например:

- топ категорий,
- топ сценариев,
- примеры запросов,
- динамика (если есть время).

Приветствуются идеи вау-фич и экстра функционала!

## Критерии оценки (на что обращаем внимание)

1. Понятность результата для CTO: отчёт должен отвечать на вопрос «что происходит и что делать дальше?»
2. Качество группировки: похожие запросы действительно вместе, разные - разделены.
3. Интерпретируемость: категории/сценарии названы понятно, есть примеры.
4. Техническая реализация: устойчивость, воспроизводимость, скорость.
5. Креатив/продуктовость: фичи, которые превращают анализ в полезный инструмент.

## Формат сдачи

- репозиторий с кодом + инструкция запуска
- входной датасет (или скрипт генерации/загрузки)
- итоговый отчёт (md/pdf) или дашборд (Streamlit/Gradio/веб)

## Вводные для датасета

Средний размер запроса пользователей: 100k токенов

Темы запросов пользователей:

1. Пользователь целый день не проверял почту и хочет получить краткую и структурированну сводку по письмам, обращается к агенту (голосом), описывает критерии важности писем и примерный шаблон саммаризации, агент выдает структурированную сводку по всем письмам в почте за прошедший день.

2. Пользователю необходимо собрать информацию по компании-клиенту, пользователь говорит агенту собрать информацию по коомпании:

   1. Кто в дочерних компаниях Директор клиента
   2. Есть ли там выигранные сделки

3. Пользователь хочет автоматизировать отслеживание писем, в которых есть запрос на расчет цен и на которые нет ответа уже в течение 2-ух часов. Пользователь говорит создать периодическое задание на мониторинг почты по определенным правилам.

4. Пользователь хочет с определенной периодичностью уведомлять фокус-группу о списке продаж, в которых были выиграны тендеры за прошедшую неделю. Пользователь говорит создать периодическое задание на сбор информации из CRM и отправке этой аналитики в почту на фокус-группу.

5. Пользователю необходимо собрать информацию по составу проектной команды и найти ответственное направление за вендора. Пользователь говорит агенту собрать информацию по критериям из CRM.

6. Пользователю необходимо собрать информацию по компании, найти информацию по ней в открытых источниках и выдать саммаризацию по аналитике конкретной компании.

7. Пользователю необходимо собрать информацию по клиенту и собрать ее в сводный отчет в Excel. Пользователь говорит агенту собрать информацию из CRM по определенному набору полей, с задачей выгрузить это в документ Excel.

8. Пользователь хочет написать отзыв руководителя в системе CoolFeedback после проведения мониторинга, сказав агенту тезисно главные моменты и договоренности после мониторинга.

9. Пользователю необходимо записать информацию перед мониторингом с сотрудником в заметку в анкетировании.

10. Пользователю необходимо добавиь новый тикет и отредактировать уже существующий в ИСУП.

11. Как менеджер по продажам, я хочу получать еженедельный отчет о выигранных тендерах за последние 7 дней, чтобы отслеживать эффективность работы отдела и планировать дальнейшие действия.

12. Как сотрудник, я хочу видеть список задач, назначенных на меня в Jira, чтобы эффективно управлять своим рабочим временем и приоритетами.

13. Как сотрудник, я хочу видеть список задач в Jira, отфильтрованных по приоритету, чтобы сосредоточиться на наиболее важных задачах и эффективно планировать свою работу.

14. Как руководитель, я хочу иметь возможность фиксировать свои наблюдения о работе сотрудников, чтобы отслеживать их прогресс и вовремя оказывать поддержку.

15. Как аналитик, я хочу иметь возможность экспортировать результаты анализа в формат Excel, чтобы удобно делиться данными с коллегами и использовать их в других инструментах.

16. Как сотрудник, я хочу иметь возможность выгружать данные в формат excel, чтобы удобно анализировать их вне системы и использовать для отчетности.

17. Пользователю необходима возможность быстро находить информацию о поставщиках в блоге, чтобы быть в курсе последних новостей и обновлений.

18. Пользователю необходимо быстро находить информацию о процессах в Confluence, чтобы эффективно выполнять свою работу и не тратить время на поиск нужных документов.

19. Как помощник руководителя, я хочу иметь возможность быстро находить свободное время в календаре руководителя и планировать встречи, чтобы эффективно организовывать его рабочее время.

20. Как руководитель, я хочу иметь возможность подтверждать выполнение задач, чтобы отслеживать прогресс команды и закрывать выполненные работы.

21. Как сотрудник, я хочу иметь возможность добавлять задачи в историю и отмечать их как выполненные, чтобы отслеживать прогресс по своим задачам и иметь полную картину выполненной работы.

22. Пользователю необходимо быстро найти свободную переговорную комнату для встречи с большим количеством участников, чтобы эффективно планировать встречи и не тратить время на поиск подходящего места .

23. Пользователю необходимо прочитать переписку с клиентом и написать ему ответ.

24. Как сотрудник, я хочу иметь возможность быстро записывать итоги обсуждений с коллегами, чтобы не забыть детали и иметь возможность вернуться к ним позже.

25. Пользователю необходимо быстро найти контакты клиента по названию компании.

26. Пользователь хочет создать встречу на большое количество коллег, дает задание агенту со списком коллег для проверки свободных слотов, совпадающих у всех.

27. Пользователь хочет узнать информацию, которая прилагалась в текстовом формате в теле встречи.

28. Создание напоминаний для пользователя по запланированным делам, например, договоренности о проведении работ после встречи с клиентом. Также позволяет автоматически структурировать и группировать список запланированных дел.

29. Пользователь хочет узнать список запланированных встреч на следующий день, чтобы подготовиться к ним.

30. Пользователь создает тикеты на доске в Project на основе пришедших писем в почте, что позволяет оперативно заводить и актуализировать тикеты на личной доске.

31. Пользователь хочет мониторить с периодичность статус проектов в ИСУП, необходимо контролировать определенные статусы и подсвечивать пользователю тот или иной переход, для оперативности реагирования.
