# Таксономия задач — v1

**Версия:** `v1` (`taxonomy_version: "v1"`). Общий словарь классов для backend, ML и frontend.
Изменение списка = контрактное изменение → bump версии и правка потребителей.

## Классы (7 + служебные)

| task_type | Ярлык (RU) для дашборда | Что включает |
|---|---|---|
| `text_generation`     | Генерация текста      | письма, инструкции, посты, ответы клиентам |
| `code_help`           | Помощь с кодом        | написание/объяснение кода, ошибки, SQL-скрипты как код |
| `data_analysis`       | Анализ данных         | Excel, аналитика, отчёты, выгрузки, SQL-запросы к данным |
| `education`           | Объяснение / обучение | «объясни», «что значит», обучающие вопросы |
| `information_search`  | Поиск информации      | сбор данных из CRM/Confluence/почты, ресёрч по компании |
| `task_management`     | Планирование / задачи | Jira/тикеты, встречи, напоминания, календарь |
| `other`               | Другое                | нерабочее, общие вопросы, аномалии |

### Служебные значения
- `unknown` — **per-record**: классификатор не уверен (confidence < порога). Это про качество
  классификации, показываем отдельно на дашборде.
- `other` — **агрегированный хвост**: категории/сценарии вне Top-N сливаются в `other`.
  НЕ путать с `unknown`.

## Почему именно этот список (7 классов)
- Совпадает с обученным датасетом (`ml_service/dataset.py`, `notebooks/prompt_radar_dataset.json`),
  `ml_service/roi_engine.py` и исходный концепт команды (стриминговый CQRS, см. `DECISIONS.md` D1).
- Соответствует примерам must-have из кейса (`docs/КРОК_case.md` §1).

## ⚠ Расхождение для согласования
`ml_service/ТЗ.md` §8.3 приводит расширенный пример из ~12 классов (`communication`,
`document_processing`, `automation_monitoring`, `non_work`, `explanation_learning` и т.д.).
Для MVP фиксируем **7-классовый v1** (на нём обучен датасет). Расширенный набор — кандидат в
`taxonomy_v2` после MVP. Финальный список — единый для всех трёх сторон, менять только согласованно.

## Правила использования
- ML присваивает ровно один `task_type` на запись (или `unknown`).
- Backend отдаёт фронту `task_type` + человекочитаемый `label` (маппинг из этой таблицы).
- Frontend не хардкодит ярлыки — берёт `label` из ответа backend.
