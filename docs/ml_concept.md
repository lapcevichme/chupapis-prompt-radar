Концепт: Промпт-радар (Микросервис аналитики ИИ-агентов)
Главная идея: Асинхронный ML-микросервис, который переваривает сырые логи агента и выдает готовую статистику для дашборда. Решение полностью обходит ограничение на H100 из ТЗ за счет использования легковесных математических моделей под капотом и делегирования ресурсоемких задач (векторизация, генерация текста) в облачные API.
Архитектура пайплайна (Два параллельных трека)
Обработка каждого запроса разделена на два независимых потока:
Трек 1: Задачи (Жесткая классификация)
Смысл: Понимание того, какую базовую функцию использует юзер.
Механика: Текст прогоняется через легковесную модель CatBoost.
Классы: Заранее заданные из ТЗ (Генерация текста, Помощь с кодом, Анализ данных, Управление задачами, Поиск информации, Общие вопросы).
Обучение: Модель предварительно обучается на синтетическом датасете (сгенерированном через LLM с добавлением шума и опечаток).
Трек 2: Сценарии (Динамическая кластеризация)
Смысл: Поиск продуктовых инсайтов и новых паттернов использования агента.
Механика (Онлайн): Запрос конкурентно (через asyncio) отправляется в облачное API эмбеддингов. Полученный вектор сравнивается с эталонными центроидами существующих кластеров (Cosine Similarity).
Механика (Батч раз в 2 часа): В фоновом режиме запускается связка UMAP (сжатие векторов) + HDBSCAN (поиск новых плотных групп и отсеивание шума).
Саммаризация: Для новых сформировавшихся ядер (кластеров) вызывается облачная LLM, которая генерирует короткое, емкое название сценария (например, "Мониторинг тендеров" или "Ошибки БД").
Интеграция с бэкендом (Паттерн CQRS)
Взаимодействие с основным бэкендом и дашбордом строится на жестком разделении записи и чтения для максимальной отказоустойчивости:
PUT /api/logs (Прием данных): Основной бэкенд кидает пачку логов. Микросервис мгновенно отвечает 202 Accepted и уходит обрабатывать данные в фоне (BackgroundTasks). Эмбеддинги собираются асинхронными батчами (по 100 мс на пачку), запросы тегируются и ложатся в БД. Бэкенд не висит в ожидании таймаутов.
GET /api/statistics (Выдача аналитики): Эндпоинт для дашборда (например, на Streamlit). Он не дергает ML-модели, а просто забирает уже посчитанные агрегированные цифры из базы данных за пару миллисекунд. Дашборд грузится мгновенно при любых нагрузках.
Главные фишки для защиты (Киллер-фичи)
Zero-GPU Architecture: Не требует мощных видеокарт, работает стабильно и дешево.
Экономия токенов: LLM вызывается не на каждый чих, а только раз в 2 часа и только для ядер сформировавшихся кластеров.
Устойчивость к аномалиям: Использование HDBSCAN позволяет системе не пытаться классифицировать откровенный мусор (свойство изоляции шума), а класс Other в CatBoost ловит нерелевантные запросы.
